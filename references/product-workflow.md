# 产品化工作流

## 目录

1. 用户边界
2. 阶段状态
3. 单一事实源
4. 增量重建
5. 截图能力适配
6. 发布契约

## 1. 用户边界

普通用户只参与两次集中选择：一次性登记事实、截图方式。若名称/版本/权属/日期/发表状态或申请范围仍有冲突，再呈现一张合并确认卡。业务理解、源码清单、分页、格式和修复属于 Agent 工作。

## 2. 阶段状态

`.工作区/workflow-state.json` 保存环境、项目分析、业务理解、基础信息、申请表、源码、截图、手册、代码、渲染、验证和发布阶段。每阶段记录输入哈希、输出哈希、完成时间和信息。输出仍存在且哈希一致时跳过；输入变化时只让依赖阶段失效。

## 3. 单一事实源

`.工作区/application-facts.json` 是所有正式材料的唯一登记事实源。业务表述来自 `business-understanding.json`，但不得覆盖已确认登记事实。申请表、手册、代码页眉、文件名和报告只从这两份模型派生。

## 4. 增量重建

- 改名称/版本：重建申请表、手册、代码页眉、PDF和报告；
- 补截图：重建截图清单、手册、手册PDF与报告；
- 修改业务功能：重建手册、申请表功能字段、源码选择与报告；
- 仅手工编辑DOCX：覆盖前保存到历史版本；不得静默丢失修改；
- 回滚：读取最近 `snapshot.json`，校验备份哈希后恢复。

## 5. 截图能力适配

浏览器或 Computer Use 是 Agent 工具层，不固化到单一平台。输出统一为 `screenshot-index.json`：稳定ID、路径、标题、章节、功能、角色、URL/窗口、动作、断言、尺寸、时间、SHA-256、质量状态和诊断。平台能力不足时切换用户截图，不伪造文件。

## 6. 发布契约

发布包必须包含 README 所列正式资料与质量检查文件。只有真实 DOCX/PDF、代码分卷、来源追溯、截图索引、一致性报告和哈希均可重新打开验证时，发布阶段才标记完成。截图跳过模式可以形成草稿正式视图，但待确认清单必须明确缺图，不能报告成全量截图通过。
