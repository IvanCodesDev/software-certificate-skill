# 40–66 页操作手册架构

## 页数策略

最终页数由真实功能数量、操作复杂度、截图数量和渲染结果共同确定：

- **40–47 页**：功能较集中的小型系统，通常包含 8–11 个核心任务。
- **48–59 页**：中型业务系统，通常包含 12–17 个核心任务。
- **60–66 页**：模块较多或流程复杂的系统，通常包含 18–22 个核心任务。
- **67–72 页**：仅用于证据充分且确有复杂配置、异常处理或多角色流程的项目。

默认使用 `plan_manual.py --target-pages auto`。自动模式最少规划 40 页，复杂项目向 60 页靠近，最高通常为 66 页。最终页数以 A4 渲染结果为准，不用重复截图、空白页或同义扩写凑数。

## 推荐页面组成

| 板块 | 建议页数 | 内容 |
|---|---:|---|
| 封面、文档身份、智能目录 | 3–4 | 软件全称、版本、权利人、真实TOC |
| 软件概述与运行环境 | 3–5 | 目标、边界、组成、部署与访问条件 |
| 角色、权限与登录 | 3–5 | 角色职责、登录、权限范围 |
| 核心业务工作流 | 4–7 | 端到端流程、状态变化和检查点 |
| 核心功能任务 | 20–38 | 每个任务1–2页，包含步骤、截图和结果 |
| 查询、统计与输出 | 2–4 | 有证据支持的查询、报表、导出 |
| 异常处理与维护 | 2–5 | 真实校验、权限、状态冲突和配置 |
| FAQ、术语、证据与版本记录 | 2–4 | 易错点、术语、截图映射、修订记录 |

## 功能页结构

简单功能使用单页：目标与入口 → 操作步骤 → 截图 → 结果。复杂功能使用双页：第一页完成任务，第二页核验结果、数据变化和真实异常路径。

## 每页内容密度

- 普通正文使用宋体 12 pt、1.5 倍行距。
- 截图页通常放 1 张主图，或 2 张具有直接先后关系的图。
- 文字页保持约 30 行有效文字；图片页按实际图文组合判断。
- 标题、图题、步骤和截图尽量保持在同一任务上下文内。

## 智能目录

使用 `TOC \\o "1-3" \\h \\z \\u` 域，Heading 1–3 设置大纲级别。刷新后检查目录文字、页码、点引导线和跳转目标。

## 逻辑审稿

每个段落都要回答：谁操作、从哪里进入、满足什么条件、执行什么动作、系统显示什么结果、证据在哪里。缺少项目证据的功能保持为内部调查项，不进入提交版。
