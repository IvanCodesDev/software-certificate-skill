# 内容驱动的操作手册架构

## 页数策略

内容充分的常规业务系统以40–60页为优选区间，并尽量接近60页。最终页数仍由真实功能数量、操作复杂度、截图数量、结果字段、业务规则、异常路径和渲染结果共同决定。`plan_manual.py --target-pages auto` 只为已有证据安排内容；小型项目可以低于40页，高级整数参数是内容上限而非填充目标。

小型命令行工具可以形成精炼手册；多角色业务系统可自然形成较长手册。重复截图、空白页、同义扩写、营销优势和无项目依据的常识段落都不计入有效内容。

## 推荐内容组成

| 板块 | 采用条件 | 内容 |
|---|---|---|
| 封面与智能目录 | 必需 | 软件全称、版本、权利人、真实TOC |
| 软件概述与环境 | 必需 | 目标、用户、边界、运行与访问条件 |
| 界面或命令结构 | 有对应证据 | 真实入口、导航、参数或窗口区域 |
| 主要工作流 | 有端到端流程 | 先后关系、状态变化和检查点 |
| 核心功能任务 | 每项确认功能 | 用途、入口、步骤、限制、反馈、截图 |
| 查询、统计与输出 | 项目确有能力 | 查询条件、结果字段、导出或摘要 |
| 异常处理 | 项目确有反馈 | 输入校验、权限、状态冲突和恢复 |
| FAQ与术语 | 内容确有必要 | 易错点、判断方法和界面术语 |

## 功能章节结构

每项功能至少形成一个完整任务闭环。查询突出筛选与结果范围，审批突出核验依据与状态变化，分析突出指标口径与判读，监控突出状态与告警，配置突出参数边界与生效反馈，文件处理突出输入输出，数据录入突出字段与校验。复杂功能拆成概览、操作、结果规则、实际异常，简单功能不机械拆页。

## 内容密度

- 普通正文使用宋体 12 pt、稳定行距；
- 一张主图应能看清页面标题、关键控件和结果；具有直接先后关系时可以并列两图；
- 图片保持比例，不为填满页面拉伸或裁切；
- 标题、图题、步骤和截图保持同一任务上下文；
- 以最终 A4 渲染页检查密度、断页和可读性，不按结构化数组条数估算实际页数。

## 智能目录

使用 `TOC \\o "1-3" \\h \\z \\u` 域，Heading 1–3 设置大纲级别。LibreOffice UNO 或 Word 刷新后，检查目录文字、页码、点引导线和跳转目标；PDF中目录页码必须与最终渲染一致。

## 逻辑审稿

每个段落都要回答：谁操作、从哪里进入、满足什么条件、执行什么动作、系统显示什么结果、证据在哪里。缺少项目证据的功能保持为内部调查项，不进入提交版。
